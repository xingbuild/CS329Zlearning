开场实验：能力没变，结局全变

同一个模型、同一批工具、同一道题——只换「接线方式」（讲义 p.35–36 原例重演）

考题：除了 Apple Remote，还有什么设备能控制「Apple Remote 最初设计所配套的那个程序」？ 下面把它分别接成三种系统。点三种模式各跑一遍（⭐ 标记的是关键帧），再看后面的分析。

剧场 · 谁拥有控制流？

LLM Core 推理 记忆 工具 环境

三个结局：纯推理幻觉出一个流畅但错误的答案（它没「看」，只有「想」）； 固定流水线每步都执行正确，却必死在 Obs 2 的歧义上（代码不读观察）； ReAct agent在同一个歧义处改道、查对、收敛。 这就是 L01 的全部秘密——能力是同一个，变的是控制流的归属。

第一幕：这个「循环」比 LLM 老五十年

讲义 p.19–27

把讲义五页历史压成一句话：循环是旧发明，新的是通用大脑。

  • 1973–1995：Actor 形式式、Society of Mind、Contract Net——多智能体协作的概念在 LLM 诞生前就在了。1995 年 Russell & Norvig 给出教科书定义：通过传感器感知、通过执行器行动的任何东西。注意，这个定义里一个字都没提 LLM。
  • 1998–2015 RL 时代：Sutton & Barto 把「agent–环境循环」形式化，DQN 在 Atari 上打赢人类。循环有了，但大脑要为每个任务从零训练——奖励稀疏、样本天价。
  • 2022 LLM 时代：in-context learning 让大脑第一次可插拔——换任务不用重训，换一份说明书（prompt）就行。ReAct（2022.10，比 ChatGPT 还早两个月）做的事，本质就是给 GPT-3 一份说明书加一个搜索框。

所以「为什么是现在」的答案不是「模型变聪明了」这么简单，而是： 控制流第一次可以用自然语言编写了。以前程序的分支写在 if/else 里，现在写在 prompt 里，由模型在运行时动态执行。

第二幕：解剖图——五条语法对应五个部件

讲义 p.29–53

讲义用 ReAct 的轨迹语法逐词映射出 agent 的五大件，这张图会贯穿整门课：

两个留待后续展开的钩子：

  • 记忆按内容分三型——episodic（存经历，追加式事件流）、semantic（存知识，LLM 对事件做推理后写入）、procedural（存技能，Voyager 存的是代码）——L07 整讲展开。
  • 推理模式是个家族——CoT、Self-Consistency（多路采样投票）、Reflexion（失败后用自然语言自我反思）、多智能体辩论、orchestrator 协调——L06 展开。

如果做过配套的 Lab 01， 你会有强烈的既视感：lab01 第 6 步的 decide → validate → execute → observe 循环就是这张图的代码化， 而那道 Pydantic 校验闸就是「概率大脑」外面裹的第一层「确定性边界」。

第三幕：全课程最重要的一刀——谁决定下一步

讲义 p.56–59 · 参考 Berkeley《The Shift from Models to Compound AI Systems》

Workflow：代码定步骤（Agentless、AlphaCode 2）—— Agent：LLM 定步骤（SWE-agent）。两者都是复合 AI 系统：LLM + 其他组件。

这不是优劣之分，是架构的第一决策，各拿一副牌：

  • Workflow：可预测、便宜、好调试——但脆，遇到剧场 Obs 2 那种「下一步取决于观察内容」的局面就死。
  • Agent：灵活、能改道——但每一步都是概率的，而概率会复利。

由此得到本讲最实用的一条判据：当下一步取决于观察的内容时，控制流必须交给模型；当下一步总是确定的时，把它焊死在代码里。 真实系统几乎都是混搭——外层 workflow 定骨架，局部 agent 处理不确定的洞。

第四幕：四大挑战 = 课程地图的另一半

讲义 p.61–70

为什么这门课后面长那样？因为 agent 有四个结构性难题，每一讲都在还其中一笔债：

  1. 可靠性：误差复利 + 三宗罪——同任务不同跑结果不一致、对 prompt/工具的小扰动敏感、失败模式不可预期。Princeton 的 HAL 仪表盘（p.63）有个刺眼的结论：能力涨得快，可靠性涨得慢——工程的价值就在这条缝里，这也是这门课存在的原因。
  2. 训练：奖励稀疏、战线长、rollout 贵。
  3. 长程：上下文增长且漂移——记忆系统因此成为必需品（L07）。
  4. 安全：任务完成 ≠ 行为安全。留三个印象：恶意弹窗对 agent 的攻击成功率 87%（它会分心）；PrivacyLens 发现 agent 行动时系统性无视隐私规范；以及多智能体合谋（L08 的暗面）。

带走三句话

  1. Agent = 循环（五十年）+ 通用大脑（三年）；新东西是控制流可用自然语言编写。
  2. Workflow vs Agent 之别只有一个问题：谁决定下一步。判据：下一步依赖观察内容 → 交给模型；总是确定 → 焊死在代码。
  3. 这门课做的一切工程，都是在给概率大脑加确定性边界，同时接受 pn 的现实并设法把 n 和 1−p 压下来。

思考题

先自己答，再展开参考答案。

1 · Lab 01 第 6 步的 mini agent 是 workflow 还是 agent？
参考答案
混搭。「调用哪个工具、填什么参数」由模型生成——这是 agent 的部分； 但「校验失败 → 报错回喂 → 重试，最多 k 次」这个外层循环、以及类型契约本身，是代码写死的——这是 workflow 的部分。 这正是第三幕判据的应用：决策点不确定 → 交给模型；控制策略确定 → 焊死在代码。
2 · 举一个「该用 workflow 却容易被诱惑上 agent」的任务，和一个反过来的。
参考答案（示例）
该用 workflow 却上了 agent：固定格式的周报摘要——步骤完全确定（读 → 摘 → 排版），agent 只会增加成本、延迟与不确定性。
该用 agent 却塞进 workflow：开放式客服退款处理——下一步是查订单、查政策还是升级人工，取决于对话内容与查询结果，观察决定行动，分支无法预先写尽。
3 · 每步 99% 可靠的 50 步 agent，端到端是多少？这个数字解释了什么现象？
参考答案
0.9950 ≈ 60.5%。它解释了：长程任务（如 SWE-bench 上的多文件改动题）的成功率远低于模型单点能力； 同一任务多次运行结果不一致（HAL 的 consistency 指标）。工程对策：缩短链（分层 workflow）、 在链中插校验闸与重试（抬高 p、把失败变成可恢复的）、对高价值步骤并行采样投票（Self-Consistency）。
