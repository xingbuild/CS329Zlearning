## 0 · 本讲资源策略

MAS 域的资源黄金组合是**同一周发布的两篇正反判据文章** + 官方框架文档 + 失败研究。论文群（MAST、CooperBench、AutoGen、Magentic-One、蜂群编译器、A2A）已挂延伸阅读——资源页补展开与实物。

## 1 · 材料清单（6 条正选）

**开场 · "先建单 agent 基线"（正反判据同周对撞）**
1. Anthropic《How we built our multi-agent research system》（图文，2025-06-13）— https://www.anthropic.com/engineering/built-multi-agent-research-system — 编排者-子代理架构、并行工具调用；**多 agent 比单 agent 提升 90.2%，代价是约 15× token**——收益与代价账本的一手数据。
2. Cognition《Don't Build Multi-Agents》（图文，2025-06-12，Walden Yan）— https://cognition.com/blog/dont-build-multi-agents — 反方判据：上下文碎片化、"Actions carry implicit decisions"、推荐单线程线性 agent。**注意域名已从 cognition.ai 迁至 cognition.com**。两文发布仅差一天——课文开场"带着怀疑进入正题"的最佳现场：同一个 2025 年 6 月，业界在同一场争论的两侧。

**第二幕 · 通信**
3. OpenAI Agents SDK 文档 — https://openai.github.io/openai-agents-python/ — **Handoff（控制权转移）概念的正典出处**（vs agent-as-tool）；guardrails、sessions、tracing 一并覆盖。
4. AutoGen（微软官方）— https://microsoft.github.io/autogen/ — "多 agent 通信 = 对话"世界观的实物（群聊/嵌套对话/层级），课文 p.32–35 的对应框架。

**第三幕 · 协调**
5. Microsoft Research《Magentic-One》出版页 — https://www.microsoft.com/en-us/research/publication/magentic-one-a-generalist-multi-agent-system-for-solving-complex-tasks/ — Orchestrator + 双账本（任务计划账本 / 进度账本）设计的官方出处；GAIA/WebArena 成绩与开源发布（aka.ms/magentic-one）。
6. （交叉引用）DeepLearning.AI《AI Agentic Design Patterns with AutoGen》的 multi-agent 章节——主放 L06 资源页，本页交叉引用。

**第四/五幕 · 失败动物园与蜂群**
- MAST（Why Do Multi-Agent LLM Systems Fail）arXiv 已在延伸阅读。**注意**：论文配套站 www.mast.systems 域名已落入一家医疗公司（301 重定向）——如页面曾引用或将来要引用，只可用 arXiv。
