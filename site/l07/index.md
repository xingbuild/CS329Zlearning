# L07 · 记忆架构

> 对应讲义 lecture07Agent Memory Architectures.pdf · p.3–100 · 约 50 分钟 · 前置：L06

L06 结束时 Pi 告诉你上下文要"聚焦 + 连续"；这一讲回答那个悬了两讲的问题——**装不进上下文的过去，放到哪里、怎么管**。一句话定位：**上下文窗口 ≠ 记忆**；记忆是一套"存什么、何时存、怎么存取"的工程系统。

## 开场：没有记忆的三种失忆

讲义 p.9 的三联症，每个用过 chatbot 的人都体会过：

- **过程丢失**：每次都要重新教 agent 怎么做这件事；
- **知识丢失**：重要事实、规则、偏好，跨会话蒸发；
- **进度丢失**：长会话做到后面，忘了目标、忘了早前的指令。

反过来，记忆买到三样东西（p.10）：**个性化**（学会你的偏好）、**经验学习**（一次学会、处处能用——Voyager 式技能积累）、**有状态**（"把我们刚才弄到一半的方案打开"）。对长时运行、多会话的 agent，这不是锦上添花，是生死线。

另一根轴同样重要（p.21）：**参数 vs 上下文**。同一份记忆可以微调进权重（便宜、快、但静态），也可以检索进上下文（动态、可解释、但占窗口与延迟）。**情景记忆在参数侧"不适用"**——你的经历没法预训练进模型，这正是外挂记忆系统存在的理由。

**How 的三种底座**（p.25–28）：

- **文件系统**：每条记忆一个文件；天然层级；**grep/ls 就是记忆工具**——让 agent 自己管自己的记忆（LangChain 的 agent builders 记忆系统）；
- **数据库**：向量库（语义检索）+ SQLite（元数据）+ BM25（精确词）——**就是 L03 那套检索栈搬过来管记忆**；
- **知识图谱**：实体关系显式连接（Zep 等）——回答"多跳关联"型问题比向量强（GraphRAG 的记忆版）。

## 第三幕：四大架构模式

**模式一：从经验学程序**（p.30–41）——把成功轨迹固化成**技能**：

- **Voyager**（Minecraft）：技能库 = 可执行代码 + 描述 + 嵌入；造钻石工具要 102 次迭代，**没有技能库则永远造不出来**——程序记忆让能力可积累；
- **AWM**（Agent Workflow Memory）：从轨迹归纳"工作流"，写进系统提示复用；
- **Skill Files**（Claude Skills）：人写或半自动维护的技能文件——通用 agent 的主流方案；
- **限制**（p.41）：对动态环境不鲁棒——环境变了，旧技能可能是错的。

**模式二：分层记忆**（p.42–49）——像操作系统管内存：

- **MemGPT**：关键洞见 **"给 LLM 一套管理自己内存的工具"**——工作上下文（RAM）+ 召回库 + 档案库（磁盘），消息 FIFO，write/replace/search 皆工具调用（认出来了吗：这又是 L04 的 A∪ℒ——记忆操作不过是动作空间里的新成员）；
- **MemoryOS**：短/中/长期 + 人格记忆的四层。

**模式三：反思式固化**（p.50–56）——存之前先想：

- **Reflexion**（L06 复习）：把失败轨迹反思成文字记忆；
- **Generative Agents**（小镇模拟）：**记忆流 + 检索三因子（时近性 × 重要性 × 相关性）+ 定期反思**生成高层洞察——"Klaus 提过喜欢摄影"这种从事件流里长出来的语义记忆。

**模式四：记忆维护**（p.57–66）——记了还要管：

- **Sleep-time Compute**：空闲时后台 agent 重新整理记忆（与 Open Claw 的凌晨 3 点整理同构——**闲时维护窗口**正在成为标配）；
- **A-Mem**：专职"记忆管理 agent"；**Mem0**：后台工作流检测冲突，四操作 **ADD / UPDATE / DELETE / NOOP**。

四个模式不是竞争关系：真实系统 = 分层底座 + 从经验长技能 + 反思后入库 + 闲时维护的**组合体**。

## 第四幕：评估——四要素与四基准

好记忆评测的四要素（p.68）：**真实**（haystack 与查询都要像真实场景）、**长上下文**（短对话测不出记忆）、**有挑战**（太简单分不出高下）、**可验证**（成败可知）。四个基准的进化史就是四要素逐步补齐的历史（p.69–92）：

| 基准 | 记忆源 | 规模 | 短板 → 下一代的改进 |
|---|---|---|---|
| LoCoMo | 模拟**用户-用户**对话 | 16.6k tok/会话 | 不真实 → 改成用户-agent |
| PersonaMem | 用户-agent 对话、偏好演化 | ~1M tok | 选择题不真实 → 改轨迹 |
| LongMemEval-v2 | **Web agent 轨迹** + 巨大海纳场 | 数亿 tok | 选择题 → 真实任务 |
| MemoryArena | 四个真实环境、约束可验证 | 数十万 tok | 四要素全绿——但空间仍巨大 |

两个刺眼的实证结论（p.73、85、91）：**① 拿到了对的记忆也未必会用**（LoCoMo：RAG 找对记忆，模型仍答错——检索不是终点）；**② 文件系统记忆打败了检索式记忆**（LongMemEval-v2——层级与命名承载的语义，胜过纯向量相似度；呼应 L03 的"分块定下限"）；**③ MemoryArena 上专用的记忆控制器反而是最弱方法**——这个领域远未收敛。

## 第五幕：开放问题

讲义 p.96–100 留了三道没有答案的题：

1. **记什么、忘什么**：写入时**不知道未来相关性**——全留则检索/上下文/维护成本爆炸，忘则可能丢证据与未完成的承诺（"这条是记忆还是玩笑？"）；
2. **信任、隐私与控制**：**记忆是攻击向量**——被投毒的程序记忆可触发危险行为；带记忆的 agent 在与世界交互时暴露隐私（PrivacyLens 线）；
3. **正确使用**：LLM 对上下文里的记忆**过度热心**——过度个性化的反面案例；检索更好 or 训练模型学会忽略，两条路都没解决。

## 带走三句话

1. 记忆 = **What × When × How 的工程系统**，不是"加个向量库"——四型（工作/情景/语义/程序）× 两轴（参数/上下文）先定类型，再谈实现。
2. 四大模式各有灵魂：**技能可积累**（Voyager/AWM）、**给 LLM 管内存的工具**（MemGPT）、**反思后入库**（Generative Agents）、**闲时维护**（Sleep-time/Mem0）——真实系统是组合体。
3. 评估四要素（真实/长程/挑战/可验证）尚无满分答卷；三个开放问题（遗忘、投毒、滥用）就是这一方向的机会清单。

  <p><b>参考答案</b>：文件系统的层级与命名本身承载语义（"2026-10/项目A/决议.md"自带时空坐标），grep 精确匹配 + ls 浏览是"结构化导航"；纯向量靠相似度猜，多跳与时序问题弱。反过来：记忆量大到无法浏览、条目无自然命名规律、需要模糊语义匹配时，检索式占优——又是结构 vs 相似度的取舍（L03 分块一课的重演）。</p>
</details>

<details>
  <summary>4 · 记忆是攻击向量：设计三条防御。</summary>
  <p><b>参考答案（示例）</b>：① 来源标记与信任分级——外部抓取的内容只进低信任记忆，触发高权限动作前需再验证（数据≠指令，L01/L03 的注入课）；② 记忆写入审计与用户可见/可删（控制权交还用户）；③ 程序记忆（技能）变更走确认流——它直接改变行为，是投毒的最高价值目标。</p>
</details>
