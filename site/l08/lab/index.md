# Lab 07 · 多智能体成本账本

> [← 返回 L08 课文](/l08/) · 纯浏览器运行，零依赖 · 约 12–15 分钟

L08 开场的那句话是工程界的金句：**"先建强单 agent 基线；加 agent 要有明确目的，并测量收益是否盖过协调成本。"** 这个实验室让这句话变成可以拨的参数：**站①** 一个六节点任务 DAG，四种拓扑真执行，消息 token 量与冲突率随你拨——看判据何时翻转；**站②** 把"交接处是信息丢失的高发地"变成 60 次蒙特卡洛：全量 Handoff、随机挑、相关性挑，三条关键事实的存活率差多少。

**怎么玩（建议路线）**：

1. 站①先用默认参数看四种拓扑的账单，读判据区的两行结论；再把"协调消息 token"拨到 1000+——中心式的判定怎么翻红的？
2. 把"蜂群冲突率"拨到 40%——观察返工与通信双杀，这是 CooperBench"协调的诅咒"的参数版；
3. 站②先按相关性挑、k=3 跑一遍（全对），再切随机挑、k=5 跑——答对率掉到多少？对照下方理论曲线找规律。

## 你刚才摸到的机制（对照课文）

| 实验室里的现象 | 课文里的名字 |
|---|---|
| 消息 token 拨高后中心式翻红 | 协调开销：委派、消息、集成吃时间吃 token（开场 p.12） |
| 冲突率 40% 时蜂群双杀 | 协调的诅咒（第四幕 · CooperBench） |
| 并行三检索只省 3 单位时延 | 收益=并行执行，但有价格（开场账本表） |
| 随机挑 k=5 会漏关键事实 | 交接处是信息丢失高发地（第二幕 p.39） |
| 相关性挑 k=3 即全对 | "挑过的上下文"——Agent-as-Tool 的工程价值 |
| 不知道哪几条关键时曲线救不了你 | 紧耦合任务一个脑子更好（p.14 左列） |

> 说明：站①的成本模型为教学版线性账（时延=关键路径、token=工作+消息），真实系统还有排队、缓存与失败重试——但**判据结构同构**（收益 vs 协调成本的比较）；站②随机策略的理论曲线是超几何分布精确解，实验是它的蒙特卡洛采样。工程保真，教学诚实。

## 零件图 · MAS 判据的三组零件（费曼检验）

**账本侧（站①）**：关键路径计算（缺 → 并行收益算不出）／协调消息计量（缺 → 成本被低估）／冲突返工系数（缺 → 蜂群永远显得划算）。
**交接侧（站②）**：关键事实集合（下游真正需要什么——缺 → 无从判断挑得对不对）／挑选策略（相关性排序——缺 → 省 token 变成丢信息）／token 预算（缺 → 只看成功率不看成本）。

**检验句**：明早有人要拆五个 agent，你能写出"先算哪三笔账"吗？——关键路径省多少、消息吃多少、冲突赔多少。
