# Lab 03 · Coding Agent 闭环实验室

> [← 返回 L04 课文](/l04/) · 站内产品化 · 约 20 分钟 · 深层连接 [L01 剧场](/l01/)（同一循环的代码域）、[pass^k 计算器](/l04/)（同一数学）、[L06 Reflexion](/l06/)（反思来自外部信号）

一个 coding agent 的完整闭环：**接收需求 → 写码 → 沙箱执行 → 测试验收 → 错误回喂 → 修复 → 交付**。要回答的根本问题只有一个：

> **概率的模型，是怎么写出确定性代码的？**

答案不在模型里，在回路上——先把验证回路关掉看裸奔，再打开看它怎么把 2/5 的失败修到 5/5。

## 第 1 站 · 闭环剧场：写码 → 执行 → 测试 → 回喂（据讲义 p.29–30 循环 × p.58 调用四步）

任务：实现 `slugify(title)`（五条可判定验收测试）。左看代码逐轮生长（新增行高亮），右看测试从 ✗ 变 ✓（结果按轮累积）——**环是结构，轨迹是展开**。

**看懂三件事**：

1. **失败是被"判定"出来的**——expected vs got 是确定性信号，不靠模型自觉（Reflexion：反思来自外部反馈）；
2. **回喂沿环回到写码位**——控制流回到自身，错误成为下一轮的上下文；
3. **出门的代码为什么确定**——同输入同输出被断言钉死；模型每步都可能错，但**验收过线的才出门**。

## 第 2 站 · pass^k 收敛模拟器：回路的概率账单

## 你摸到的机制 ↔ 课程对照

| 实验室现象 | 课程概念 |
|---|---|
| 测试把失败**判定**出来 | 可判定验收 = RLVR 的部署版（[L02 训练管道](/l02/)：单元测试/精确匹配当奖励） |
| 回喂沿环回到写码位 | 循环是结构（[L01 剧场](/l01/) 同一环，代码域重演） |
| 关掉验证器 → 3 个 bug 上线 | "任务完成 ≠ 正确交付"；pass^k 是部署口径不是研究口径 |
| p=50% 抬到 97% | 1−(1−p)^k（[L04 pass^k 计算器](/l04/) 的蒙特卡洛实证；Monkeys：15%→56%） |
| 新增行逐轮减少 | 修复在收敛：错误信息越具体，下一轮越短 |
