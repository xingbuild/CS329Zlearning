# Lab 01 · Structured I/O 实验室

> [← 返回 L04 课文](/l04/) · 站内产品化形态（v2）· 约 25–35 分钟 · 亦服务 [L02](/l02/)（约束解码）与 [L06](/l06/)（最小 ReAct）

把 L04 的根基——**结构化输出**——亲手跑一遍。核心命题一句话：**LLM 的输出本来是对自然语言的概率采样；工程要做的，是把它变成对形式语言的概率采样**——在概率与符号之间架设类型契约。语法可判定（可 100% 保证），语义不可判定（只能逼近）。

**演进逻辑**（从软到硬）：prompt 里求它 → 解码时逼它 → 协议里打包它 → 闭环里依赖它。

硬约束登场：**文法 → NFA → token 掩码**，非法 token 在采样前就被清零。契约 `{"name": <字母>, "age": <数字>}`，亲手步进：

三件事看清：① 合法集随前缀实时变化（`lov` 此刻合法、`ada` 此刻非法）；② 数字区连 `true`/`"` 都进不来——**保证由构造而来，不是靠检查**；③ 语法 100% 合法的代价是**语义仍不保证**（age=99 照样合法）——所以现实系统是掩码 + 校验闸双层。GBNF/Outlines/OpenAI strict 模式都是这一机制的产品化包装。
