# Lab 05 · 模式组装台

> [← 返回 L06 课文](/l06/) · 纯浏览器运行，零依赖 · 约 12–15 分钟

L06 给了你九种"被实践验证过的循环形状"（五工作流模式 + 四推理行动模式）——Fowler 说**模式是半成品，你总要自己把它烤熟**。这个实验室就是烤炉：**站①** 三个真实系统场景，七块积木随你拼，拼完运行评审，讲义判据逐槽对答案；**站②** 把"Reflexion 为什么必须依赖外部反馈"变成可跑的对照实验——自评与外反馈的纠错率，蒙特卡洛真算。

**怎么玩（建议路线）**：

1. 站①先拼"客服工单系统"（思考题 1 的现实版）——注意第 ⑤ 个槽：有一块积木叫「确定性代码」，想想它该放哪；
2. 运行评审后读每槽的判据理由，再切"技术调研报告"（STORM 简化版）与"代码评审机器人"；
3. 站②连跑四五轮——看"自评"那根红条为什么常常比"无反思"还矮。

## 你刚才摸到的机制（对照课文）

| 实验室里的现象 | 课文里的名字 |
|---|---|
| 分流槽放「路由」、固定串联放「提示链」 | 工作流五模式的各自定义域（第一幕 p.15–20） |
| 退款执行槽的正解是「确定性代码」 | 思考题 1 底线："退款执行本身是纯代码 workflow，不交给模型" |
| 跨文件影响分析槽放 ReAct 才得正解 | "下一步取决于观察内容"——L01 那把刀（第二幕） |
| 技术调研场景 = 并行化 + 编排者 + 链 + 评估循环 | STORM 一次用齐四模式（第一幕 p.22–29） |
| 自评把对的改错（22%）压过改对（15%） | Huang 2023：LLM 自评降低性能（第二幕 p.41） |
| 外部反馈 82% 改对、几乎不改错 | 可判定信号：测试不会恭维模型（Reflexion 的前提） |

> 说明：站②的"答题"用概率表 + 伯努利采样模拟（教学版）；"改对率/改错率"两个参数依据 Huang et al. 2023 的定性结论设定（自评净伤害、外反馈净收益）——**调这两个参数再跑**，你会看到结论翻转的条件：什么时候自评也能赢？（答案：当 breakIt 远小于 fix 时——即模型自评真的可靠时，可它并不可靠，这正是论文的题眼。）

## 零件图 · 模式选型的三组零件（费曼检验）

**组装判据（站①）**：分支可写尽？（能 → 工作流模式；不能 → ReAct）／执行涉钱涉权？（是 → 确定性代码，缺它 = 引狼入室）／验收有判据？（有 → 评估者-优化者，没有 → 循环到天亮）。
**反思机制（站②）**：信号来源（外部可判定 vs 内部自评——缺判定 = 越改越错）／改写动作（错题改对的概率）／副作用（对题改错的概率——最容易被忽略的零件）。

**检验句**：不回看积木盒，你能说出"路由"和"编排者-工人"的分界线是什么吗？——提示：一个分的是**类别**，一个分的是**任务**。
