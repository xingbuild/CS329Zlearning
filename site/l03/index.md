# L03 · RAG：外挂知识器官

> 对应讲义 lecture03RAG Agents.pdf · p.9–63 · 约 45 分钟 · 前置：L02 · **配套实验：[Lab 02 · RAG 交互实验室](/l03/lab/)（把本讲管道亲手跑一遍）**

L02 说过：模型的全部知识冻结在参数里，上下文是唯一的工作记忆。这一讲解决那个显而易见的推论——**模型不知道的事，怎么让它"先查再答"**：把长期知识外包给检索系统，把大脑留给推理。

## 开场：同一个大脑，两种答案

讲义 p.10 的原例。问题：**"本周哪个 office hour 人最少？"**

- **LLM 单打**："试试周三下午的场次——周中通常人最少。" ——流畅、自信、像那么回事，**纯属编造**。
- **LLM + 检索**：检索到队列日志（"近三周：周二 16 点平均 14 人排队；周四 9 点平均 3 人"）→ "周四 9 点，你前面大约 3 个人。"

注意两者的大脑是同一个。差别只在：一个用参数记忆冒充事实，一个拿到了 just-in-time 的证据。RAG 给你三样东西（p.11）：**动态性**（文档随时增删，不用重训）、**可解释性**（生成可以带引用指针）、以及把"记忆"从参数里挪出来的**成本优势**。

## 第一幕：Retriever–Reader 框架，以及"RAG"一词的两副面孔

讲义 p.12–21。经典框架（DrQA，2017）：

```
Retriever  f(D, Q) → P1…PK     （从 N 篇文档里捞出 top-K 段落，K 预定义如 100）
Reader     g(Q, {P1…PK}) → A   （阅读理解：从段落里抽答案）
```

而 **RAG 原论文**（Lewis et al., 2021，p.16–17）是把这个框架概率化：检索器 $p(z\mid x)$ 给 top-K 段落，生成器 $p(y\mid x, z)$ 逐 token 写答案，整体按检索器置信度**边际化**：

$$p(y\mid x) \approx \sum_{z \in \text{top-}K} p(z\mid x)\, p(y\mid x, z)$$

两个变体（p.16）：**RAG-Sequence**（选一个段落生成整句答案）与 **RAG-Token**（**每个 token 都重新挑段落**）。检索器用 DPR（双塔 BERT + 最大内积搜索 MIPS，p.18），生成器用 BART，**联合训练**最小化负边际对数似然。

> **术语考古（重要）**：今天业界说"RAG"，指的是"检索结果拼进 prompt 再生成"这个**工程套路**；论文里的 RAG 是**联合训练的端到端模型**。一词两义，读文献时先分清对方在说哪个。

分块的四代策略（p.24）：**固定大小**（100–500 token；太小向量没上下文，太大一个向量摊平多个主题）、**语义/结构切分**（按句子、标题）、**上下文增强**（每块附加元数据或摘要）、**AI 动态切分**（让 LLM 找自然边界）。重叠 10–20% 防止句子在边界上消失。

三种"给块注入上下文"的进路（p.26–34）：

1. **Contextual Retrieval**（Anthropic，p.27–29）：用 LLM 给每个块生成一句"它在全文中的位置说明"再嵌入——检索失败率显著下降；配合**混合检索**（向量管语义、BM25 管精确词）效果更佳。
2. **Late Chunking**（p.30–31）：长上下文编码器先嵌整篇、再按块边界池化——不加 token 不调 LLM，上下文直接进向量。
3. **层级索引 RAPTOR**（p.32–33）：自底向上建树——块 → 聚类 → LLM 摘要 → 再嵌入 → 重复。**细节问题命中叶子，主题问题命中上层节点**（灰姑娘例：主题题由摘要层答，细节题由叶子层答）。**GraphRAG**（p.34–35）更进一步：LLM 从文档抽实体关系建图，按社区摘要做全局问题。

最后是**向量的物理层**（p.36–38）：精确检索是暴力扫描 O(N·d)；实际都用 **ANN 近似最近邻**——IVF（聚类只探近心）、PQ（向量压缩成短码）、**HNSW**（多层邻近图，从顶层贪心下跳，~log N 跳高召回）。工程认知一句话：**你在用的"向量搜索"是用一点召回换大量速度的近似**。

## 第三幕：检索侧——三代检索器与它们各自的失效面

讲义 p.40–54。

**BM25（2010 年代仍在王座上）**（p.41）：词项得分 = **IDF（词多稀有）× 词频饱和（出现越多分越高、但边际递减）× 长度归一（长文档不占便宜）**。它抓**精确词**：ID、报错码、产品名。

**DPR（2020）**（p.43–48）：双塔结构——query 和段落各自过 BERT，向量内积即相关度；对比学习训练（in-batch 负例 + BM25 难负例）。关键数字：**1000 对 QA 数据就够在 5 个数据集的 4 个上打败 BM25**——语义匹配（改写、同义）是它的主场，稀有字面量是它的盲区。

**两两失效面不同 → 混合检索**（p.49）：双路各出一张 ranked list，用 **RRF 倒数秩融合**合并（只看排名不看分值，k=60，无需按语料调参）。**重排**（p.50）：bi-encoder 快但粗，cross-encoder 把 query+段落拼一起过模型（全注意力）精但慢——所以工业标配是**漏斗**：BM25/DPR 粗筛千级 → cross-encoder 精排十级。

**ColBERT（晚交互）**（p.51–53）：每个 token 存一个向量，query 与段落独立编码、打分时才交互（MaxSim 求和）——词级证据、精度高，代价是索引按 token 膨胀。**快慢阶梯**（p.54 原表）：

| 检索器 | 延迟量级 | 赢在 | 死在 |
|---|---|---|---|
| BM25（稀疏） | 62 ms | 精确词：ID/报错码 | 改写、同义词 |
| DPR（双塔） | 数十 ms | 语料级语义匹配 | 稀有字面量；需标注对 |
| ColBERT（晚交互） | ~458 ms | token 级证据 | 索引按 token 膨胀 |
| Cross-encoder | 秒级/千段 | 短名单上的精度 | 无法扫全库（只能做重排） |

**评估指标**（p.45–46）：Hit@k（top-k 里有没有相关段，不管位置）、MRR@k（第一个相关段的排名倒数）、Recall@k（找回了多少相关段）、nDCG@k（带位置折损的排序质量）。**先测检索再怪模型**——大多数"模型答错"其实是 Hit@k 为零。

## 第四幕：Agentic RAG——把检索变成动作

讲义 p.56–61。前面的一切只回答"怎么检索得好"；但一个真正的问题还剩三个决策（p.56 原话）：

> **(1) 到底要不要检索（还是直接答）；(2) 该发什么查询；(3) 结果够不够好。**

眼熟吗？这正是 L01 的判据——**当下一步取决于观察内容时，控制流交给模型**。静态 RAG 把这三问焊死在代码里；Agentic RAG 把检索变成 agent 动作空间里的一个工具：

- **Self-RAG**（p.57）：模型学会**边生成边反思**——用特殊的反思 token 决定"该检索了 / 这段证据相关 / 这个回答有据"，检索、批评、生成一体。
- **CRAG**（p.58）：给检索结果配一个**评审员**——先给召回质量分级，再决定用、重查、还是上网补。
- **Search-R1**（p.59–61）：不再手工设计策略，**用 RL 学搜索策略**——多轮"推理 ↔ 检索"轨迹端到端优化（连回 L02 的 RLVR：可验证奖励 + 可判定的成败）。

一条清晰的技术演进线：**固定管道 → 模型自己决定何时查 → 训练把这个决定练进模型**。

## 带走三句话

1. RAG = **把知识从参数搬到检索**：换来回动态性、可解释性与成本优势；代价是整条管道的失败面。
2. **分块是第一决定、检索是第二决定**：分块定下限（上下文完整性），检索器按失效面选型与混搭（精确词 BM25、语义 DPR、词级 ColBERT、精度 cross-encoder），漏斗式粗筛精排。
3. Agentic RAG 的本质一句话：**把"要不要查、查什么、够不够"三个决策从代码移交给模型**——又是 L01 那一刀。

## 思考题

<details>
  <summary>1 · 你的 RAG 系统答错了，给出一个 10 分钟的排查顺序。</summary>
  <p><b>参考答案</b>：先测检索（Hit@k / Recall@k：证据进没进 top-k）→ 再看分块（关键信息是否被切散、被截断）→ 再看阅读（证据在上下文里但被中间丢失/干扰项带偏？重排与裁剪）→ 最后才是模型与提示。绝大多数"模型笨"其实是前两步。</p>
</details>

<details>
  <summary>2 · 为什么"混合检索 + RRF"几乎总比单检索器好？RRF 为什么用排名不用分值？</summary>
  <p><b>参考答案</b>：BM25 与稠密检索的失效面互补（字面 vs 语义）。RRF 只融合排名，因为两路的分值量纲完全不可比（BM25 的分数与余弦相似度没有换算关系），排名是唯一的公共货币；k=60 压平头部差异、免调参。</p>
</details>

<details>
  <summary>3 · Self-RAG 的反思 token 与 lab01 的校验闸，本质是同一种东西吗？</summary>
  <p><b>参考答案</b>：同构不同层。校验闸是<strong>代码级</strong>的可判定检查（语法/类型，100% 保证）；反思 token 是<strong>模型级</strong>的自评（"我认为该检索了/证据相关"，概率保证）。前者守护确定性边界，后者在语义不可判定处做近似判断——两层叠加才是完整方案（lab01 的"语法可判定、语义只能逼近"再度应验）。</p>
</details>
